# 하네스 목적 (R2)

> 참조: [R1-A-story-service.md](R1-A-story-service.md)(서비스 기준), [R1-B-story-work.md](R1-B-story-work.md)(작업 방식). 두 문서는 섞지 않는다.

목적:   화면 1개를 입력받아, uibowl 레퍼런스 수집 → 분석 → 화면 설계서 →
        Figma 키 스크린 시안(390×844)까지 만든다. (R1-B-story-work.md 1~4번)
입력:   화면 1개 (예: "스킬 라이브러리 화면")
사용자: 나 혼자 (디자이너)
범위 밖: 5번 컨셉 확정(내가 기획/개발자와 직접), 6~7번 토큰·컴포넌트·가이드 검토

## 완료 기준 (전부 충족 시 완료)

- C1. 레퍼런스 ≥ 5건 수집 (uibowl URL 포함)
- C2. 분석 파일에 "가져올 것" 항목이 1개 이상, 각 항목에 근거 레퍼런스 번호가 있음
- C3. 화면 설계서 1건이 있고, PRD 16장 핵심 화면 10개 중 하나임
      (홈, 무료 학습자료, 유료 멤버 자료실, 스킬 라이브러리, 미션 상세, 제출 화면, 내 학습, 내 자산, 자산 상세, 운영자 검수)
- C4. Figma 키 스크린 프레임 1개, 크기 390×844
- C5. design.md 위반 0건 (모서리 0/16/24/9999만, 그림자 0, accent는 상업 신호에만, …)
      상세 항목은 R5에서 확정

## 메모

- C2는 기계가 "항목 수와 근거 유무"까지만 센다. 내용이 맞는지는 사람 판단(R1-B-story-work.md 2번 게이트)이며 R5에서 사람 승인 지점으로 다룬다.
